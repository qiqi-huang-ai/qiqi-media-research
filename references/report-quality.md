# 报告交付质量标准

这份 Skill 的验收对象不是“接口是否成功”，而是用户能否据报告做出下一条内容决策。

## 短提示词不降级

用户只说“分析这个博主”“看看最近热点”或“帮我找选题”时，按模式默认合同补全分析维度。报告不得因为用户没有逐项指定字段，就退化成接口结果摘要。缺少目标细节时采用创作者决策视角，并在“研究任务”中公开这一默认值。

## 必须呈现的原始作品字段

搜索类报告逐条列出：标题/发布文案、作者、发布时间、视频时长、原始链接、播放量、点赞、评论、分享、收藏和互动率。缺失字段写“未返回”，不要用 `0` 填充。

## 必须完成的分析层

- 热门原因：说明是结果承诺、低门槛、场景价值、互动信号还是其他因素，并指向作品级数据。
- 用户痛点：统计评论样本中的问题类别和出现次数；评论很少时标为方向性信号。
- 开头钩子：有逐字稿/画面证据才写成已观察；否则写“根据标题/文案推断”，并给出复核动作。
- 内容结构：有时间轴或逐字稿才拆成开头、演示、结果、CTA；否则只输出候选结构，不冒充镜头分析。

## 爆款与趋势

单条爆款至少同时给出作品指标和样本基线；共同趋势要列出覆盖账号数、作品数和重复主题。只有一个账号出现的主题必须标为个案，不能写成平台趋势。

## 单一来源交付

Markdown 是内容真源，PDF 由同一 Markdown 渲染。PDF 可以增加图表和视觉层级，但不得改变数字、样本量、链接、结论强度或证据边界。内部 evidence ID 和证据类别只保留在 `analysis/findings.json`，面向用户的 Markdown 与 PDF 都使用自然语言。

## 信息密度

- 不用基础画像、排行榜和空章节堆长度。
- 每个排行榜后必须回答“相对什么基线”“与普通/低表现样本差在哪里”“是否重复出现”。
- 主题分布必须同时给出主题数量和主题表现；多标签计数不能伪装成互斥占比。
- 建议必须连接到样本、基线和验证方法。换一个账号仍然成立的泛化建议应删除或改写。
- 账号审计按 `account-audit.md` 验收；无视频证据时只能分析公开标题/文案，不能生成虚假的视频内部拆解。

## 组合研究的最低证据链

当一个请求同时包含“热门内容 + 用户痛点 + 原创选题”时，关键词搜索只能负责发现候选，不能独立完成整份报告。至少需要：

1. 对搜索结果按明确时间边界过滤。
2. 对进入排名的抖音作品补取真实播放量。
3. 同时保留高表现作品和普通表现基线，避免只看爆款。
4. 对代表作品采集评论并跨作品统计问题类别、评论数和覆盖作品数。
5. 选题逐条说明所依据的作品、评论需求和竞争判断；没有需求证据的创意标为探索性选题。

## 自动验收

`analysis/delivery-audit.json` 是交付门：

- `ready`：关键身份字段、原始证据、标准化数据、报告和时间过滤均通过，指标覆盖达到阈值。
- `ready_with_caveats`：证据链完整，但部分互动指标缺失；必须在研究边界中披露。
- `failed`：缺原始证据、身份字段、时间过滤记录、标准化数据或报告；不得作为成熟案例交付。

组合研究可把单作品详情和评论保存在研究根目录的子目录中；验收器会递归检查原始证据。最终 Markdown 完成后运行：

```bash
python3 -m scripts.delivery_audit research-output/任务目录 \
  --report research-output/任务目录/reports/final.md
```
