# 短提示词的成熟交付合同

用户不需要懂研究方法。只要对象和意图足以判断模式，就把短提示词扩展成该模式的默认研究合同；不要因为用户没有逐项列要求，就退化成账号简介、搜索结果摘要或接口字段罗列。

## 自动补全原则

1. 从链接、平台名、关键词和动词判断主模式；主页链接优先路由 `account-audit`，作品链接优先路由 `viral-breakdown`。
2. 用户未说明目的时，采用“帮助创作者判断现状、规律、可复制性和下一步动作”的默认目标，并在研究任务中写明。
3. 用户未给时间范围时，不虚构“近期”；账号审计明确作品样本的实际首尾日期，搜索研究说明未设置时间窗。
4. 用户未给样本量时，先使用不超过 20 次调用的最小成熟样本。预计超过 20 次时说明增量价值并等待确认。
5. 只有目标对象缺失、链接无法解析、平台冲突或需要扩大付费调用时才追问。其他缺省项由模式合同补全。
6. 报告先回答“所以该怎么判断和行动”，再列数据；原始作品明细放在“附录：原始作品明细”，不用大段接口字段替代分析。

## 各模式默认必须回答

| 模式 | 短提示词也必须回答的核心问题 |
|---|---|
| niche-discovery | 有哪些细分方向；供给和表现如何；需求信号在哪里；先验证什么 |
| trend-scan | 观察时间点；热度证据；单点事件还是重复趋势；持续性和跟进窗口 |
| competitor-discovery | 候选是谁；为何入选；各自内容与数据基线；与用户目标的适配和优先级 |
| account-audit | 账号事实；更新与表现基线；高低表现对照；文本模式；评论需求；可复制与不可复制；下一步 |
| viral-breakdown | 作品相对账号基线；可见文本钩子；互动和评论信号；能借鉴什么；什么仍需视频复核 |
| comment-mining | 评论覆盖；需求类别和计数；代表原话；高频与高价值需求；内容/产品动作 |
| content-gap | 已有供给；评论需求；供需错位；空白证据；可验证选题 |
| cross-platform | 两个平台各自样本和口径；同义指标对照；内容差异；迁移建议，禁止直接比原始热度分 |
| brand-product | 公开提及规模；正负疑问和使用场景；代表作品/评论；可验证传播机会，不作真实性鉴定 |
| idea-generation | 每个选题的证据来源、切入角度、目标用户、形式、验证指标和升级方向 |
| market-map | 市场边界；主体与主题分组；供需结构；机会区；样本不能覆盖什么 |

## 成熟报告的共同结构

- 一页结论：3–7 条能直接影响行动的判断。
- 研究对象与口径：平台、时间、样本、调用和缺失情况。
- 数据基线：中位数优先，均值仅作补充；区分累计指标与标准化指标。
- 分组对照：至少比较高表现与普通/低表现，不能只列 Top 榜。
- 模式结论：用作品、账号或评论证据支撑，不把单条个案写成趋势。
- 行动建议：说明依据、适合谁、先怎么小规模验证。
- 研究边界：写清哪些结论已验证、哪些是文本推断、下一步如何提高确定性。

内部 evidence ID 和证据类别写入 `analysis/findings.json`，不要在面向用户的 Markdown 或 PDF 中展示 `[interpreted]`、`evidence: post:...` 等机器表达。
